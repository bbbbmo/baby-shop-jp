# 사이트를 하나로 할까, 둘로 할까

COMO를 일본 손님과 한국 손님이 같이 쓰게 만들려고 합니다.
방법이 두 가지라서 하나를 골라야 합니다.

이 글은 **개발을 모르는 사람에게 설명하려고** 쓴 것입니다.

*(아래 주소는 예시입니다. 실제 주소는 아직 정하지 않았습니다.)*

---

## 1. 어차피 달라져야 하는 것들

일본 손님과 한국 손님은 **같은 화면을 볼 수 없습니다.**

| | 일본 손님 화면 | 한국 손님 화면 |
| --- | --- | --- |
| 가격 표시 | `¥12,000` | `35,000원` |
| 가격 자체 | 대행 수수료·국제배송비 포함 | 국내 판매라 더 쌈 |
| 배송비 | 5,000엔 이상 무료 / 550엔 | 3만원 이상 무료 / 3,000원 *(미정)* |
| 주소 입력 | 우편번호 7자리, 후리가나 필요 | 우편번호 5자리, 도로명주소 검색 |
| 화면 언어 | 일본어 | 한국어 |

여기까지는 **어느 방법을 골라도 똑같이 해야 하는 일**입니다.

진짜 고민은 이겁니다.

> **이 두 화면을 한 사이트 안에 둘 것인가, 아예 다른 사이트로 만들 것인가?**

---

## 2. 방법 하나 — 사이트는 하나, 주소만 나눔

사이트는 하나입니다. 주소 뒤에 `/jp` 또는 `/kr`이 붙습니다.

```
como.com/jp            일본 손님 첫 화면
como.com/jp/products   일본 손님 상품 목록
como.com/jp/cart       일본 손님 장바구니

como.com/kr            한국 손님 첫 화면
como.com/kr/products   한국 손님 상품 목록
como.com/kr/cart       한국 손님 장바구니
```

- 주소만 보면 어느 나라 화면인지 바로 압니다.
- **회원 정보, 상품 목록, 주문 내역은 한 곳에 모여 있습니다.**
- 관리자 화면도 하나입니다. 여기서 일본 가격과 한국 가격을 같이 입력합니다.

---

## 3. 방법 둘 — 사이트를 아예 두 개

주소부터 다른, 서로 남남인 사이트 두 개를 만듭니다.

```
como.jp            일본 손님용 사이트 (전부 따로)
como.jp/products
como.jp/cart

como.kr            한국 손님용 사이트 (전부 따로)
como.kr/products
como.kr/cart
```

- 주소를 두 개 사야 합니다.
- **회원 정보도, 상품 목록도, 관리자 화면도 두 벌**입니다.

---

## 4. 실제로 뭐가 달라지나

### 손님 입장

| 상황 | 사이트 하나 | 사이트 두 개 |
| --- | --- | --- |
| 회원가입 | 한 번만 하면 됨 | **일본 쪽·한국 쪽 각각 가입해야 함** |
| 로그인 | 어느 화면에서든 로그인 상태 유지 | 사이트를 옮기면 **로그아웃 상태로 보임** |
| 장바구니 | 담아둔 게 그대로 있음 | 사이트를 옮기면 **비어 있음** |
| 주문 내역 | 한 곳에서 다 보임 | 두 사이트에 나뉘어 있음 |
| 카카오·구글 로그인 | 한 번 연결하면 끝 | 사이트마다 따로 연결해야 함 |

### 운영 입장

| 할 일 | 사이트 하나 | 사이트 두 개 |
| --- | --- | --- |
| 새 상품 올리기 | 한 번 등록, 가격만 두 개 입력 | **두 사이트에 각각 등록** |
| 재고 관리 | 한 곳에서 셈 | 두 곳이 어긋나 **품절인데 팔릴 수 있음** |
| 잘못된 것 고치기 | 한 번 고치면 양쪽 반영 | **두 번 고쳐야 함** |
| 회원 문의 대응 | 회원 명부 하나 | 어느 쪽 회원인지 먼저 찾아야 함 |

### 그 밖에

| | 사이트 하나 | 사이트 두 개 |
| --- | --- | --- |
| 구글·네이버 검색 | 조금 불리 | **각 나라 검색에서 더 잘 노출됨** |
| 나라별 법정 안내문 | 화면마다 갈아 끼움 | 사이트별로 깔끔하게 분리 |
| 주소(도메인) 비용 | 한 개 | 두 개 |
| 만드는 기간 | 짧음 | 김 |

---

## 5. 우리가 고른 것

> ### 사이트는 하나. 주소만 `/jp`와 `/kr`로 나눔

### 결정적인 이유는 로그인입니다

사이트를 두 개로 만들면
**`como.jp`에서 로그인해도 `como.kr`에서는 로그인이 풀립니다.**

인터넷 사이트는 로그인 상태를 주소 단위로 기억하기 때문입니다.
주소가 다르면 다른 사이트로 취급합니다. 이건 우리가 바꿀 수 없습니다.

그래서 이런 일이 생깁니다.

- 같은 사람이 **가입을 두 번** 해야 합니다.
- 카카오·구글·라인 로그인도 **양쪽에 각각 연결**해야 합니다.
- 일본에서 산 주문 내역을 한국 쪽에서는 볼 수 없습니다.
- 손님이 "나 가입했는데요?" 하면 설명이 길어집니다.

우리는 지금 막 카카오 로그인과 약관 동의 절차를 붙였습니다.
사이트를 나누면 **이걸 두 벌로 관리**하게 됩니다.

### 두 번째 이유는 상품 관리입니다

같은 옷을 두 사이트에 각각 올려야 합니다.
값을 바꿔도 두 번, 품절 처리도 두 번입니다.

특히 **재고가 어긋나는 게 위험합니다.**
일본 쪽에서 마지막 하나가 팔렸는데 한국 쪽에서 또 팔리면,
손님에게 취소 연락을 해야 합니다.

### 포기한 것

사이트를 두 개로 만들면 좋은 점도 분명히 있습니다.

- **구글·네이버 검색에서 각 나라 사람들에게 더 잘 노출됩니다.**
- 나라마다 붙여야 하는 법정 안내문을 깔끔하게 나눌 수 있습니다.

아쉽지만, 지금은 로그인 문제가 더 큽니다.
손님 수가 적을 때 검색 노출보다 **가입·주문이 막히지 않는 게** 중요합니다.

---

## 6. 나중에 바꿀 수 있나

**바꿀 수 있습니다.**

지금은 `como.com/jp`, `como.com/kr` 형태로 만들지만,
나중에 손님이 늘면 `como.jp`, `como.kr`로 나눌 수 있습니다.

그때 다시 만들어야 하는 건
**"손님이 어느 나라 화면으로 들어왔는지 알아내는 부분" 한 군데뿐**입니다.

가격 계산, 배송비, 주소 입력, 상품 관리는 지금 만든 걸 그대로 씁니다.
그래서 지금 결정 때문에 나중에 발이 묶이지 않습니다.

---

## 한 줄 정리

> 사이트를 두 개로 나누면 **같은 손님이 가입과 로그인을 두 번** 해야 하고,
> **상품과 재고도 두 벌**로 관리해야 합니다.
> 그래서 **사이트는 하나로 두고 주소만 `/jp`·`/kr`로 나눕니다.**
> 나중에 필요하면 그때 나눌 수 있습니다.
